# Ассоциативные массивы на Mac mini M4 Pro

Все измерения выполнены последовательно на одном Mac mini M4 Pro под macOS 27.0.1. Параметр питания powermode равнялся 0. Каждый образец охватывает миллион операций в одном потоке. Для каждой пары реализации и сценария собрано семь образцов. Отдельного разогрева нет. Статья приводит медианы.

## Файлы

- [samples.csv](../results-mini-native/samples.csv) хранит все первичные замеры Rust, C и C++. Столбцы без заголовка: реализация, тип ключа, число элементов, операция, номер повтора с нуля, нс/операцию.
- [go.jsonl](../results-mini-native/go.jsonl) и [bun.jsonl](../results-mini-native/bun.jsonl) содержат медиану и минимум из исходного стенда. Метрика памяти использует собственный счетчик среды выполнения.
- [workload.mjs](workload.mjs) генерирует входной файл и вычисляет контрольные суммы через JavaScript Map.
- [bench.rs](bench.rs) реализует Rust-замеры. [native.cpp](native.cpp) управляет замерами C++ и C. [cmap.c](cmap.c) и [cmap.h](cmap.h) реализуют операции на C.
- [uthash.h](uthash.h) взят из [uthash v2.3.0](https://github.com/troydhanson/uthash/blob/v2.3.0/src/uthash.h). Лицензия BSD находится в заголовке. SHA-256 файла: `344175d0ae3d0d7651887f932fc224f6d133559f0fc83ee73fe641697d77211a`.

## Воспроизведение

Команды выполняются из каталога с этими файлами. Входной формат использует little-endian. Для генератора использован Bun 1.4.3, для бинарника Rust - rustc 1.98.0 (88d9e12ae, LLVM 22.1.8, aarch64-apple-darwin). Бинарник Rust собран на другом arm64 Mac, подписан ad hoc и перенесен на стенд. C и C++ собраны на стенде Apple Clang 21.0.0 (clang-2100.3.34.2), SDK 27.0, libc++ 220106.

```sh
bun workload.mjs 1000000
shasum -a 256 workload.bin
rustc --edition 2021 -O bench.rs -o blog-map-rust
codesign -s - -f blog-map-rust
clang -O3 -flto -c cmap.c -o cmap.o
clang++ -std=c++20 -O3 -flto native.cpp cmap.o -o native

(
  ./blog-map-rust rust int 7
  ./blog-map-rust rust str 7
  ./blog-map-rust rust-id int 7
  ./native cpp int 7
  ./native cpp str 7
  ./native uthash int 7
  ./native uthash str 7
) > reproduction.csv
```

Контроли Go 1.27.1 и Bun 1.4.3 используют [исходный стенд](https://github.com/haiodo/map-bench/tree/38dc643f782173f957f5ab80a21912d25fc0be77). Команды выполняются из корня той версии. Для автономной сборки Go нужны заранее загруженные модули.

```sh
(cd go && GOMAXPROCS=1 GOPROXY=off go run ./cmd/mapbench -impl '^go/map$' -sizes 1000000 -reps 7) > go.jsonl
for k in int str; do
  bun js/mapbench.mjs --sizes 1000000 --impl js/Map --keys "$k" --reps 7
done > bun.jsonl
```

## Методика

Mulberry32 с seed 42 дает два непересекающихся набора по миллиону положительных либо нулевых 31-битных ключей. Для строк ключ имеет вид `key-0962696645`. Вставка строит таблицу последовательно. Поиск использует порядок вставки либо второй набор. Смешанная трасса выбирает чтение, запись и удаление с вероятностями 50%, 30%, 20%. Каждая операция выбирает второй набор с вероятностью 25%. Таблица предварительно заполнена для всех сценариев, кроме вставки. Измерение удаления включает освобождение удаляемых узлов для реализаций, которые его выполняют. Уничтожение оставшейся таблицы происходит после остановки таймера.

Генерация ключей, строк и трассы происходит до измерений. Все два миллиона ключей и миллион закодированных операций сверены с оригинальным генератором JavaScript. SHA-256 входа: `66497684848604ef1dd6193f0fc19c733276822cc1baff8e3fe919d9ccf4e7f6`. Сумма успешных чтений равна 1072723225291532. После mixed в таблице 944868 записей. Сумма чтений mixed равна 381070061367235 для целых и 336111414179378 для строк. После каждого нативного замера стенд проверяет размер и сумму чтений либо обхода.

Rust использует HashMap с RandomState или тождественную функцию хеширования для u32. Вариант insert_hint включает время резервирования. C++ использует std::unordered_map со стандартным хешером. C использует uthash с HASH_JEN и отдельное выделение памяти под запись. При добавлении или обновлении C вычисляет хеш один раз. C хранит указатель на заранее подготовленный ключ. Rust хранит u32 либо &str, C++ хранит uint32_t либо string_view. Массив std::string в C++ служит общим хранилищем коротких строк для C и C++; Rust формирует отдельный String для каждой строки. Расположение строк в памяти отличается.

В нативных реализациях ключи и значения целого типа имеют ширину 32 бита. Go использует uint64, JavaScript - Number. В трассе Rust/C/C++ индекс и код операции упакованы в одно слово. Исходные Go и Bun используют свои структуры трассы, интерфейсы и правила сборки мусора. Нагрузка совпадает по содержанию, измерения включают стоимость этих различий.

## Парный прогон Rust 1.98.0 и 1.100.0

[Rust 1.98.0](../results-mini-native/rust-1.98.0-paired.csv) и [Rust 1.100.0](../results-mini-native/rust-1.100.0-paired.csv) содержат по семь повторов на метрику. Обе версии установлены официальным rustup и собраны из одного bench.rs с флагами `--edition 2021 -O`. Использованы компиляторы для aarch64-apple-darwin: 1.98.0 (88d9e12ae, LLVM 22.1.8) и 1.100.0 (0ef1bc386, LLVM 23.1.5). Сборка с явным выбором версии:

```sh
for v in 1.98.0 1.100.0; do
  rustup run "$v" rustc --edition 2021 -O bench.rs -o "map-$v"
  codesign -f -s - "map-$v"
done
```

Бинарники последовательно запущены на Mac mini с одним workload.bin. Внутри каждой конфигурации версии идут подряд: для rust int и rust-id int первой идет 1.98.0, для rust str - 1.100.0. Команды аналогичны основному прогону. Сохранен режим powermode 0. Во время измерений системная служба mediaanalysisd использовала 112% CPU. Для сравнения версий используйте два парных файла, исходный прогон 1.98.0 выполнен отдельно.

Для int RandomState сделан повтор в обратном порядке: [сначала 1.100.0](../results-mini-native/rust-1.100.0-repeat-int.csv), [затем 1.98.0](../results-mini-native/rust-1.98.0-repeat-int.csv), последним [исходный бинарник Homebrew 1.98.0](../results-mini-native/rust-1.98.0-homebrew-repeat-int.csv). Медианы lookup_hit в повторе составили 44.010, 60.467 и 71.107 нс/операцию соответственно. Отдельные значения официальных версий пересекаются. Историческую разницу абсолютных таймингов воспроизвел даже тот же бинарник Homebrew; причина отличия условий не установлена.
